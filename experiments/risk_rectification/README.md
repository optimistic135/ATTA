# PACS D100：当前软伪监督与风险残差校正的最小验证

## 实验问题

在相同查询计划、初始化、监督抽样和正式更新次数下，迟到真值构成的加权残差能否改善当前软伪监督的作用？

固定：Photo(source) → Art → Cartoon → Sketch，batch32，D=100，seed=110/123/456。只运行三个方法 × 三 seed，共九个任务，不增加其他延迟、参数搜索、外部预训练模型或 CLIP。

| 运行名 | 正式损失 | 回答的问题 |
| --- | --- | --- |
| SP-ATTA | 原 SP 损失 | 基础参照 |
| SP-CurrentSoft | SP + η × 当前软损失 | 使用当前源目标是否有益 |
| SP-RiskRectify | SP + η ×（当前软损失 + 加权历史真值减软损失） | 整个残差校正项是否有额外价值 |

默认 η=0.25。两个辅助组使用完全相同的启用条件、当前图像、软分布及系数，不替换原监督更新，也不减少原真值系数。

## 方法公式与实现

### 保留 SP 基础训练

\[
L_{SP}=\operatorname{CE}_{M_t}(y,p_\theta)+\lambda_tL_{history},\quad \lambda_t\in\{0,0.25\}.
\]

复用完整返回记忆、SGD、学习率、momentum、原 SP 反馈门控、每批训练配额与抽样。门控影子候选仍是原 SP 损失，不加入新辅助项。轨迹分叉后门控判定可以不同，这是辅助项的后续影响。

当前 pool 仅含本批新图像，不使用置信度筛选。软目标 q 来自原冻结源模型，覆盖所有类别，不锐化、不变硬标签、不校正分类头。标签尚未返回的图像可缓存源特征/概率，但不得使用其真值。

所有目标概率和权重停止梯度。缓存采用本批训练前的源输出；冻结源模型不变化，因此历史查询概率在返回后仍可复用。

### 分布比近似

源编码器特征做 L2 归一化，输入一个线性二分类器。历史已返回记忆为0，当前 batch 为1；损失是两组 BCE 均值的等权平均。两类先验平衡时：

\[
\hat w(z)=\exp(a^Tz+b).
\]

CPU float64，从零初始化，用解析全批梯度迭代50次，lr=0.5、L2=0.01。不使用真实类别、Torch 全局随机数、额外神经骨干或 autograd。

两折估计：记忆按 anchor 顺序交替分折，当前图像按批内位置交替分折；仅用另一折历史/当前特征拟合，预测留出折。两折结果拼接，减少直接在拟合样本上估计自身密度比。它不构成针对自适应在线学习的完整统计交叉拟合保证。

原始比值先截断到[0.2,5]，再在完整记忆中归一化为均值1。**归一化后的权重不一定仍落在[0.2,5]。** 同时记录原始 ESS、截断归一化后的 ESS、截断比例、逐样本原始/归一化权重和留出分布分类准确率。

两个辅助组共同要求：已返回记忆≥16、当前 batch≥4、截断后 ESS≥8，且本批有正式训练配额。否则都回退原 SP。此处是稳定性启用条件，**不是通过了分布重叠检验**；截断可能人为提高 ESS，高分类准确率可能表示两组易区分，也不等于密度比校准良好。

### 有界软损失与残差

仅对新增辅助项，定义：

\[
\bar\ell_y(x)=-\log\max(p_\theta(y|x),10^{-4}),\qquad
\bar\ell_q(x)=-\sum_cq(c|x)\log\max(p_\theta(c|x),10^{-4}).
\]

这相当于截断辅助损失的 log-probability，不重新归一化概率；原 SP CE 不变。对负软损失项设置界，避免该辅助目标向负无穷下降。

\[
L_U=\frac1{|U_t|}\sum_{x\in U_t}\bar\ell_q(x),
\]

\[
\Delta_t=\frac1{|M_t|}\sum_{(x,y)\in M_t}\bar w(x)
\left[\bar\ell_y(x)-\bar\ell_q(x)\right].
\]

SP-CurrentSoft 加 ηL_U；SP-RiskRectify 加 η(L_U+Δ_t)。实际每个正式训练步，Δ_t 使用**该步原本的真值 minibatch**无偏于有限记忆均匀抽样均值的 Monte Carlo 估计，不额外选择有利的标签。

代码镜像原父循环的真值/历史抽样顺序，生成残差对应的缓存位置，并最终核对计划抽样哈希与实际正式抽样哈希。复用已算出的真值 logits 计算残差，不多做一次该 minibatch 的骨干前向。

残差可以为负，不将其裁成正数；辅助风险估计也可能为负。所有非有限概率、权重和总训练损失触发失败，不悄悄当作完成。

## 这次验证与理论方案的边界

为保持与原 SP 的固定查询对照，**本轮不加入随机探索查询**。现有主动查询可能存在选择偏差或零覆盖；特征空间密度比、有限样本、时序漂移、权重截断和归一化也均会引入近似。因此，只称“风险残差校正实验”，不能自动称无偏风险估计或已经实现双重稳健保证。

原真值系数始终为1；残差又包含 η×加权的有界真实损失。因此，该组真实监督总影响增强，并同时减去历史软损失。`extra_bounded_truth_coefficient` 明确记录这一点。**三个组只能识别整个残差项的作用，不能单独证明减法优于单纯增加真实监督。** 若结果积极，下一轮才有理由加“仅增加同量真实监督”的消融；本轮严格不加第四组。

首次反馈前不增加更新；没有真值无法做残差校正。因而 D100 Art 和首次反馈前预测应保持一致，不能承诺恢复等待期损失。

## 风险估计诊断

所有组都计算相同的冻结源缓存、密度比拟合与训练前记忆诊断，作为匹配的额外诊断开销：

\[
\widehat R_{proxy}=L_U,\quad
\widehat R_{rect}=L_U+\Delta_t.
\]

这里诊断Δ_t用完整已返回记忆，在**本批正式更新之前**计算；训练中的Δ_t则用原真值 minibatch。

当前 batch 的真实标签只在 batch-end 离线评分：使用更新前保存的 logits，得到实际有界 batch 风险，计算 proxy/rectified 估计绝对误差。三组在相同 eligible batch 上评价，先 seed 内按 batch 样本数加权，再跨 seed 汇总。

风险 MAE 变小不保证梯度方向更好；相同标量损失可以有不同梯度。因此，本轮不将 MAE 改善当成方法有效的充分证据，也不把它用于在线门控、调参或训练。

## 服务器运行

从仓库根目录、原 PyTorch 环境运行；无新增外部包或检查点要求：

```bash
python -u -m experiments.risk_rectification.run \
  --dataset-root datasets \
  --reference-dir storage/simatta_rootcause/pacs_d100_bs32_seeds110_123_456 \
  --gpus 0 1 \
  --seeds 110 123 456 \
  --output-dir storage/risk_rectification/pacs_d100_seeds110_123_456
```

`--reference-dir` 是已完成的原 SimATTA 根因诊断根目录，复用查询ID/时间、返回时钟、逐批正式配额及源检查点哈希。它不是 SP、FCRA 或本实验输出目录。检查点路径不同时加 `--checkpoint-dir 路径`；单卡改为 `--gpu-idx 0`。

断点后在相同命令末尾加 `--resume`。跳过完整任务，部分任务和旧汇总先归档后整次重跑；不从半途训练状态恢复。设置、参考、检查点或受审查代码哈希变化时使用新输出目录。双卡每张GPU至多一个任务，沿用逐域和总任务进度条。

## 输出与判断

- `summary.md` / `summary.csv`：三方法各域、全流、宏平均、首次反馈前/后准确率，查询/返回/跨域比例、成本和权重/风险诊断。
- `per_seed.csv`：九个任务的结果。
- `paired_gains.csv` / `paired_summary.csv`：CurrentSoft−SP、RiskRectify−CurrentSoft、RiskRectify−SP，含各域和反馈阶段；先按 seed 相减，再求均值/样本标准差。
- `risk_by_domain.csv`：每 seed、每方法、每域的 eligible 样本量、两种风险估计 MAE 和权重诊断。分域汇总只作离线评价，不参与算法。
- 每个方法/seed 下 `risk_batches.csv`：风险估计、离线真实风险、源目标正确率及源正确/在线错误、源错误/在线正确计数；这是目标机会，不是实际训练纠错。
- `risk_losses.csv`：逐正式训练步当前损失、带符号残差、辅助项、真实/历史系数及额外有界真值系数。SP 行的辅助项为空、η=0。
- `density_weights.csv`：逐批、逐历史样本权重；以及原 SP 的 batches/domains/feedback/gates/updates/budget/local_future.csv、compute.json、settings.json、最后写入的 result.json。

正式更新次数不变，密度拟合 CPU 迭代另记 `density_updates`；诊断和新增当前图像前向/反向的额外成本由计数器、耗时与峰值显存报告。相同 optimizer.step 数不等于相同 FLOPs 或相同真实监督强度。

优先检验 RiskRectify−CurrentSoft 的逐 seed 在线收益，再看 RiskRectify−SP。若只比有害的 CurrentSoft 好，却不超过 SP，就没有恢复 SP 之外的性能。若辅助组实际启用为零，则未检验到辅助机制；若仅少数 seed 受益，不宣称稳定提升。风险 MAE、ESS 或当前目标准确率的改善不能替代正式在线收益。
