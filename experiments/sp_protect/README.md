# SP-Protect：保护当前可信区域的延迟监督适应

## 研究问题与最小实验

历史真值是否在纠正模型时破坏了当前已经掌握的预测？保护这部分预测能否改善后续在线准确率？

只做 PACS：Photo(source) → Art → Cartoon → Sketch，batch=32，D=100，seed=110/123/456。两个方法 × 三个 seed，共六次运行：

| 方法 | 正式训练损失 | 比较目的 |
| --- | --- | --- |
| SP-ATTA | 原 SP 真值监督 + 原门控历史辅助监督 | 复现参照 |
| SP-Protect | 原 SP 损失 + 当前可信预测 KL 保护 | 判断保护是否有额外价值 |

仅新增 `experiments/sp_protect/`；保留所有既有代码、模型和结果。不加载 CLIP，不引入额外预训练模型、分类头或适配器。使用原有在线模型和冻结源模型。

## 方法

### 1. 在预测时缓存可信区域

每批首先完成原在线预测，再用原冻结源模型对原图和水平翻转图预测。候选满足源模型最大概率 ≥0.9，且两种视图类别一致。从候选内部按源置信度取前 `ceil(0.1 × 候选数)`，不是固定取全 batch 的 10%。空候选直接跳过保护项。

完全同分时，用独立、按 seed/batch 确定的随机次序打破平局；不消耗原训练的全局随机序列。

对选中集合 C_t，缓存本批训练开始前的**在线模型软概率**：

\[
q_i=\operatorname{sg}\left[p_{\theta_t}(x_i)\right],\quad x_i\in C_t.
\]

源模型只负责选择图像，不提供保护目标。q 不锐化、不变成硬标签、不刷新，不对原图目标使用翻转视图训练。目标和保护前向使用同一视图。

### 2. 用返回真值纠错，用可信区域限制遗忘

\[
L=L_{\mathrm{truth}}+\lambda_tL_{\mathrm{history}}+
\beta\frac1{|C_t|}\sum_{i\in C_t}D_{\mathrm{KL}}\left(q_i\parallel p_\theta(x_i)\right).
\]

- 真值监督系数保持 1；完整已返回真值池、原训练 minibatch、SGD 学习率和 momentum 均复用 SP。
- λ_t 沿用原 SP 新反馈门控，取 0 或 0.25。
- β 固定为 1.0，不做参数搜索；这是尚待验证的默认值。
- 保护项只加入 SP-Protect 的正式训练；SP 的影子候选仍使用原门控目标。轨迹分叉后门控判定可以不同，这属于该修改的后续影响。
- 原逐批优化次数不变，不另加保护优化器或额外训练步。但保护会增加骨干前向/反向计算。
- 没有真值、没有原训练额度时，不单独训练保护项；因此首次反馈前不改变预测。

由于参考 q 就是训练前的在线输出，在 dropout=0、冻结 BN 的本配置中，第一次梯度更新前 KL/梯度应接近零。它主要约束同批后续多步训练的漂移，**不是向第一步注入新的类别知识**。

所有预测先于标签到期与训练。保护缓存不读取标签，真值按原 oracle 到期；流末不冲刷；不利用真实域边界重置。

## 受控条件与诊断

六次运行从原 Photo 检查点独立开始。`--reference-dir` 指向已完成的原 SimATTA D100 根因诊断；读取其查询 ID/时间、返回时钟和正式更新配额，不读取未来真值作训练决策。

程序在汇总时检查两组同 seed 的参考哈希、正式抽样哈希、伪标签池哈希、保护选样哈希、查询/返回数和逐批配额一致。首次反馈前预测哈希也必须一致。两条训练轨迹及门控接受情况不要求一致。

两个方法都运行相同的源置信度选择和更新后诊断前向，避免诊断只出现在一组。只有 SP-Protect 把保护项纳入损失。相同步数不等于相同 FLOPs；汇总另外报告骨干前向/反向调用与图像数、源模型前向数、影子步数、耗时和峰值显存。

记录三类效果，避免混淆：

1. **正式在线效果**：每批更新前的各域、全流、域宏平均和首次反馈前/后准确率，按 seed 配对相减。这是主要结论。
2. **当前区域保护效果**：更新前后，对同一批选中图像统计正确→错误、错误→正确、KL，以及离线源预测正确率。标签只在 batch-end 评分，不影响保护目标。此处已经训练过这些图像，只能说明即时变化，不能替代泛化结论。
3. **后续十批描述**：对有反馈返回且后续十批完整的时刻，比较两条持续训练轨迹的未来在线准确率，按未来真实域拆分。窗口可能重叠，不是独立重复；也不是冻结分支实验，不能归因于某一次返回标签。

## 服务器运行

不需要安装新模型包或下载权重。在仓库根目录、原实验环境运行：

```bash
python -u -m experiments.sp_protect.run \
  --dataset-root datasets \
  --reference-dir storage/simatta_rootcause/pacs_d100_bs32_seeds110_123_456 \
  --gpus 0 1 \
  --seeds 110 123 456 \
  --output-dir storage/sp_protect/pacs_d100_seeds110_123_456
```

源检查点不在默认位置时加 `--checkpoint-dir 路径`；单卡把 `--gpus 0 1` 换成 `--gpu-idx 0`。双卡每张卡至多一个任务，沿用逐域与总任务进度条。

中断后用同一命令加 `--resume`。完整任务按 `result.json` 及必要输出校验后跳过；部分任务和旧汇总先归档到 `_resume_archive/`，随后从该任务开头重跑。不恢复半途训练状态。配置、参考或受审查代码哈希改变时使用新输出目录。

## 输出与判断

根目录：

- `summary.md` / `summary.csv`：准确率、反馈比例、训练与计算成本、可信区域变化，三个 seed 均值 ± 样本标准差及有效 n。
- `per_seed.csv`：六个任务的原始结果。
- `paired_gains.csv` / `paired_summary.csv`：先按 seed 计算 SP-Protect − SP，再汇总；主要看 Stream、Cartoon、Sketch。
- `trained_region_effects.csv`：仅有正式训练的 batch，分域统计可信区域纠错、致错和源预测正确率，排除等待期无更新样本的稀释。
- `future_windows.csv`：按返回时刻和未来域的后续十批描述性差值，不将这些重叠窗口作为统计独立重复。

每个 `SP-ATTA/seed_*` 或 `SP-Protect/seed_*`：

- 原 SP 的 `batches.csv`、`domains.csv`、`feedback.csv`、`gates.csv`、`updates.csv`、`budget.csv`、`local_future.csv`、`compute.json`。
- `protection_selection.csv`：选中样本 ID、源置信度、源和在线类别。
- `protection_losses.csv`：逐次正式训练的 KL、保护样本数和 β；SP 对照只有表头。
- `protection_batches.csv`：所有当前图像及选中区域更新前后纠错/致错，首次反馈阶段和返回数。
- `settings.json`、最后写入的 `result.json`；运行根目录有 `manifest.json`，保存检查点、参考文件和实验/关键依赖代码哈希。

可支持方法的结果应同时满足：正式在线准确率有稳定的配对改善，并且可信区域致错减少；只有当前图像 KL 下降或更新后准确率增加不够。

如果保护项只让模型不再变化，或者保护了错误预测、伤害 Cartoon/Sketch 的后续准确率，就不支持这条路线。它不补足首次反馈前的类别知识，不能改善已经结束的 D100 Art 等待期；该域两组一致是预期。

尚未运行验证，也不预填效果或声称机制已经成立。本地仅静态阅读和差异检查，未执行 Python、测试、实验或训练。
