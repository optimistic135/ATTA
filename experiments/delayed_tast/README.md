# Delayed TAST：等待期适应、迟到真值重放与记忆修复

## 实验范围

固定 PACS：Photo(source) → Art → Cartoon → Sketch，batch=32，D=100，seed=110/123/456。只做三个组×三个seed，共九个任务。无新预训练资源、CLIP、参数搜索或额外数据集。

| 运行名 | 训练与推断设计 | 核心问题 |
| --- | --- | --- |
| TAST-Online | TAST式邻域适应，真实类别不进入正式预测/更新 | 等待期邻域适应是否改善冻结源预测 |
| TAST-Replay | 同一路径 + 已返回真值监督重放 | 迟到真值能否提供额外收益 |
| TAST-Repair | 与Replay相同监督抽样 + 真值修复支持标签/邻居投票 | 修复记忆是否进一步改善当前目标与在线表现 |

本目录独立新增，既有实验与结果不改动。**TAST-Online 是受控在线版本，不是原论文完整复现**：本实验采用已有 ResNet18 Photo 检查点、预测先于更新、连续跨域不重置，并使用下述共同支持样本控制。

## 共同支持集合：避免容量混淆

原始TAST按源预测类别保留低熵支持样本。主动查询往往挑到高熵图像；若仅修复仍留在该低熵库中的查询，可能大量真值根本无法参与。

为隔离“真实标签”与“多存了样本”的影响，三个组都使用完全相同的支持样本ID：

1. **低熵库**：每个源预测类别保留20个最低源熵样本，支持特征来自冻结骨干。选择始终用源预测类别/熵，与真实标签和适应头无关。
2. **返回查询槽位**：所有已返回查询的特征都恢复到共同支持集合，哪怕已经从低熵库淘汰；低熵库与返回槽位按ID去重。
3. Online/Replay组对所有槽位继续使用源预测标签；只有Repair组使用已返回真值。返回查询特征不因其真实类别被淘汰，真值不被后续伪预测覆盖。

因此，特征数量、ID、保留规则与内存容量在三组一致。**这个共同返回槽位本身改变了原始TAST的支持策略**；本轮不另加第四个原版TAST组，也不将本组表现声称为论文复现结果。

Online组执行同一查询/返回时钟，以匹配支持ID，但不使用返回的真实类别进行实际预测或训练。它可在离线诊断副本中读取已经到期的类别。表中的查询成本属于共同实验协议，不是无监督TAST固有的标注需求。

## 方法实现

### 冻结骨干与轻量投影

原Photo编码器E和源线性分类器W全部eval且requires_grad=False。每批只编码一次，特征不参与骨干反向。

采用五成员共享权重、秩一缩放的线性投影集合：

\[
h_e(z)=\gamma_e\odot V(\alpha_e\odot z)+b_e.
\]

输入维度为原编码器输出，投影维度为其1/4；V、α、γ采用Kaiming-normal初始化，b为0。三个组同seed使用相同初始化，原分类器权重行作为初始支持向量，初始类别由源分类器预测这些向量得到。

每个成员根据支持标签形成投影后的类别均值，再用归一化余弦相似度×10得到原型分类logits。邻居在**冻结源特征空间**按余弦相似度取最近4个，不利用真实域边界。

原TAST思路会先用投影原型分类器重新分类支持样本，再对邻居的硬预测构建训练目标、对软概率投票生成预测。Repair组的已知真值支持点，类别投票和概率投票都固定为真实类别one-hot；未返回点仍用原机制。真值同时改变类别原型、邻域训练目标和邻域预测，三组不能进一步分离这三条作用路径。

### 一步更新与重放

所有组每个batch做**一次**Adam更新，lr=1e-3，状态跨域保留。TAST式无监督目标为各成员KL之和，分别按batch×类别数归一化，保持官方代码的缩放约定。

Replay/Repair在已有返回标签时，用完整返回池均匀有放回抽16个样本，计算原型分类器CE，各成员求和后除以类别数；系数固定1。与KL一样归一化，避免两个目标因类别维度的缩放不同而失衡。两个组用完全相同的ID抽样和步数；Online生成相同抽样记录但不将其类别用于损失。

不增加独立监督优化步，不把监督权重按记忆池大小稀释；不存在返回标签时Replay/Repair完全沿用Online路径。

**没有复用旧SP的逐批训练额度。** 旧额度在等待期为0，无法验证等待期适应；本轮三组统一每批1次轻量头更新。相同的是三组内部更新次数，不宣称与旧SP骨干训练相同预算或FLOPs。已有SP结果仅作上下文参照。

## 时序与标签隔离

每批顺序固定：

1. 当前图像经冻结编码器提取特征。
2. 使用此前已有支持集合和头参数预测，缓存正式在线输出。
3. 做相同快照的标签修复诊断；只使用此前已返回标签。
4. 当前无标签特征进入低熵库；按原reference ID发出查询。
5. oracle释放到期标签，将对应特征恢复到三个组共同支持集合。
6. 构建当前训练目标，做一次轻量更新；Replay/Repair可使用本次新到期真值。
7. 当前真实标签只用于离线评价缓存预测与目标，不参与选择、适应或诊断决策。

新返回标签最早改变下一批的在线预测。首次返回批次仍计入before-feedback。整条流连续计时，不按真域重置，不在末尾冲刷pending。再次入库同ID不会覆盖已返回真值；本PACS流不重复图像。

## 最小诊断

### 等待期是否有效

每批同时评分原冻结源分类器，无额外GPU任务。比较before-feedback的TAST在线预测与相同图像的冻结源预测。三个方法在该阶段应有相同预测哈希。

### 真值是否真正改善当前目标

每个组、每批在**同一头参数、相同支持特征/ID**下，比较两种副本：支持继续用源标签 vs 已返回标签修复并固定其投票。比较：

- 邻域训练目标的平均分布argmax正确率、纠错/致错数；
- 邻域软概率输出的argmax预测净变化；
- 当前图像的邻居中是否直接包含真值锚点。

这两种副本都在本批当前图像入库和新标签释放之前计算，只作诊断，不能反向影响训练。`repair_exposure`只统计直接邻居，不覆盖通过类别原型发生的间接影响。

实际训练目标在当前入库与释放之后生成，另存`actual_training_target_prediction`与正确率，不能与上述训练前反事实目标混淆。

这些目标质量诊断不能证明未来收益；主结论仍来自三组正式在线准确率和seed配对差值。不同组已具有不同头状态，不能把跨组目标精度差值当作同快照干预效果。

## 服务器运行

在仓库根目录、原实验环境运行，不安装TAST仓库或新包，不下载检查点：

```bash
python -u -m experiments.delayed_tast.run \
  --dataset-root datasets \
  --reference-dir storage/simatta_rootcause/pacs_d100_bs32_seeds110_123_456 \
  --gpus 0 1 \
  --seeds 110 123 456 \
  --output-dir storage/delayed_tast/pacs_d100_seeds110_123_456
```

原reference用于固定查询、返回时钟、源检查点和流结构，**不用于本方法训练配额**。需要保持数据集原样；原reference没有每张原图的内容哈希，不能检测所有同尺寸数据替换。

单卡改`--gpu-idx 0`；检查点位置不同时加`--checkpoint-dir 路径`。中断后同命令加`--resume`，跳过完整任务，部分任务及旧汇总归档后从头重跑。不恢复半途头状态。配置/代码/参考哈希改变时用新目录。双卡一卡一个任务，逐域和总任务进度条保持原样。

## 输出与判据

- `summary.md/csv`：各域、全流、宏平均、反馈前后准确率；源模型等待期参照；查询/返回/跨域比例；重放/修复覆盖；耗时与显存。
- `per_seed.csv`：九个任务原始结果，含冻结源与头初始化、源特征、支持ID和重放抽样哈希。
- `paired_gains.csv` / `paired_summary.csv`：Replay−Online、Repair−Replay、Repair−Online；先seed配对相减，再均值/样本SD，含各域和阶段。
- `repair_by_domain.csv`：每seed、每组、每域和反馈阶段的同快照目标/预测修复诊断。
- 每任务`batches/domains/feedback/updates.csv`、`returned_labels.csv`、`target_repair.csv`、`compute.json`、`settings.json`、最后写的`result.json`。
- `target_repair.csv`逐图记录训练前反事实目标/输出、实际训练目标、真实评价类别、正式在线预测和直接锚点覆盖。评价真值只写记录。

判断顺序：

1. Online等待期能否超过冻结源；否则不能声称解决了等待期适应。
2. Replay能否超过Online；否则没有证明迟到监督的新增价值。
3. Repair能否超过Replay，并在同快照诊断中出现稳定净纠错；否则不支持记忆修复贡献。

若只是当前目标变准而正式在线没有增益，不能声称方法有效；若真值锚点错误邻接导致更多致错，就应停止这条迁移假设，而不是叠加阈值模块。

该方案不是已经验证的新颖算法；与TAST及已有记忆修复/标签传播存在重合。贡献是否成立要由延迟设置下的受控结果支持。
