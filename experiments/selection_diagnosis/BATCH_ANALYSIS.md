# 现有日志的同批次筛选分析

## 研究问题

上一轮的前10%是在整个warmup域内事后排序，不能直接代表在线每批前10%。本分析只读取已有日志，不再训练模型，检验：

1. 每批少量高置信目标是否仍然高精度，且不只出现在少数后期批次？
2. 可靠性排序反向是否随时间、域或查询人群而改变？
3. 返回训练记录里究竟有多少“校正改对/改错”的差异监督，何时真正进入风险训练？

## 输入与固定设计

输入为已经完成的`selection_diagnosis`根目录，使用manifest中的全部三个seed，不筛选seed。读取每seed的`score_observations.csv`、`query_scores.csv`、`feedback.csv`、`shadow_updates.csv`、`batches.csv`、settings/result以及根manifest。

不需要原图、数据集目录、检查点、GPU、PyTorch或第三方统计库。代码仅依赖Python标准库。源CSV与原汇总不修改。

### 主分析：当批新图像

用batches.csv的样本数累计得到当前批ID区间，只保留该区间的图像。每个图像在主分析中只出现一次。

仅分析warmup后的批次。在各分支自己的“允许使用＋置信度>=原阈值0.9＋翻转一致”集合中，固定k=ceil(0.1N)，非空至少选1个：

- 源/校正分支原置信度最高k个；
- 对应可靠性分数最高k个；
- 同一候选集合均匀随机选k个的期望正确数。

另保留低分k个。两种排序共用候选集合和k。没有风险0.8门槛，也不改变模型或真实在线决策。边界同分按均匀概率分配权重，完全同分时不会利用图像顺序制造排序优势。随机项是可精确计算的期望，不启动随机训练。

记录每批候选数、k、实际覆盖率、零候选批次比例和预期正确数。N较小时实际覆盖率可能明显大于10%，不能把规则名称当成实际覆盖率。

### 时间稳定性与窗口对照

每个域自己的warmup后批次按时间分为early/middle/late，再跨seed报告。它们不是整个域或整个流的前三分之一；例如Cartoon可能只覆盖其后期。

主指标按各批预期正确数之和 / k之和计算，不能把每批准确率简单平均。分域与各时段结果用于判断高精度是否集中在少数批次。

最近4批滚动窗口用同样规则额外分析，标记`rolling_window`；它包含重复图像，边界还可能含旧域图像，只作补充。正文优先解释`current_batch`。

本版不验证warmup前的Art目标质量；Art表为空不代表Art没有可信子集，更不代表等待期适应已解决。

## 查询偏差

分别比较所有新图像、已查询、已返回查询、pending查询、未查询图像：

- `full_stream`：全流，便于观察总体构成差异；
- `returned_query_steps`：仅包含已返回查询发生过的批次，减少流尾时间混合；
- 严格批内配对：每个批次用其已返回查询人数作为权重，对该批未查询样本计算相同人数的期望正确数，再合并。

最后一项避免“某批查询很多、另一批未查询很多”造成不一致时间权重。没有未查询对照的批次排除并报告数量。即使如此仍是描述性人群差异，不证明查询是唯一因果因素。

学习前/后及warmup后按照观测或查询发生时的模型状态划分。pending组的评分只使用离线评估真值，不能当作在线可用反馈。所有真值都不用于拟合或调阈值。

## 校正案例与差异反馈时序

在同一图像上统计四类：两者都正确、两者都错误、校正改对、校正改错。报告净纠错和差异标签比例：(改对+改错)/样本数。

已返回训练记录使用query_scores.csv保存的查询时正确性；当前图像使用事后评估正确性，不混用两种状态。

另外对齐shadow_updates.csv：

- 首次返回不同正确性标签的时间；
- 首次实际抽中这种记录训练风险模型的时间；
- 此类记录的训练draws与全部风险训练draws。

校正头开始变化后，新查询还要等待D批才能返回差异反馈。本实现两个风险输出零初始化且共享输入，早期监督若相同，难以形成差异；审计用于验证该瓶颈，不声称所有算法都必然有同样的延迟下界。

输入审计还比较保存查询预测与当时窗口重算的正确性、分数和置信度。若出现较大差异，应先排查对齐或数值问题，再解释查询偏差。

## 服务器命令

```bash
python -u -m experiments.selection_diagnosis.analyze_batches \
  --input-dir storage/selection_diagnosis/pacs_d100_seeds110_123_456
```

默认输出到原目录下`batch_analysis/`，保留父目录全部原始结果。可用`--output-dir PATH`指定新的分析目录。

相同命令加`--resume`：输入哈希与分析配置相同、且完整输出哈希校验通过时直接跳过；未完成分析归档到`_batch_analysis_archive/`后重新汇总CSV，不重跑任何训练。输入或已完成报告被改动时拒绝覆盖，要求新目录。

## 输出与优先阅读顺序

1. `summary.md`：主结果、时段、查询偏差、案例和差异训练时序。
2. `ranking_per_seed.csv` / `ranking_summary.csv`：先看current_batch，不只看跨seed均值。
3. `per_batch.csv`：检查可用数量与高精度是否集中于少数批次。
4. `matched_bias_*`：同批查询人数加权后的查询/未查询差异。
5. `query_bias_*`：全流、相同时间范围及学习阶段的补充对比。
6. `correction_cases_*`：配对改对/改错、双方同正确性标签比例。
7. `input_audit.csv`：对齐差异和首次差异反馈/训练时间。

`*_per_seed.csv`保存每seed指标；`*_summary.csv`跨三个seed计算均值±样本标准差，保留有效n。不把图像、批次或重复窗口作为独立seed，也不自动作显著性声明。

## 结果如何决定下一步

- 同批高置信目标持续高精度且数量可用：再验证小比例当前辅助的局部/整流效果；目标精度不等于训练收益。
- 高精度只在全域事后排序出现：不能直接部署该规则，也不能把原99.27%作为每批可达精度。
- 风险排序不优于置信度：不优先调风险门槛；先定位监督人群、时间与差异标签不足。
- 差异反馈首次进入训练很晚：warmup总体样本数不等于已有充分的校正优势监督，不能只延长或放宽阈值来宣称解决问题。
